## 二、项目关键约定（必须遵守）

1. **模块模板**：`api/{front,backend}/<mod>/v1/`（g.Meta 声明式路由）+ `internal/modules/<mod>/{service,logic,controller/{front,backend},router.go}` + `internal/model/entity/`。logic 直接用 `g.Model()`，无 dao/repo（老模块 user/finance 等有 repo，新模块不用）。
2. **路由**：统一挂 `internal/cmd/router.go` 的 mountFront（`/front/v1`，前缀是字面量）/ mountBackend（`/backend`，业务接口挂 perm 权限组）。前台需登录的用 `middleware.Auth + middleware.UserRateLimit` 子组。
3. **后台列表筛选参数**：status（及可为 0 的筛选值如 user_id）一律 **string 接收**，空=全部，"0"/"1" 精确——避免 int 传空与 0 歧义（tag 模块的教训）。
4. **幂等/并发**：条件更新 + RowsAffected 判定（防超卖/防透支/状态机）；InsertIgnore（PG ON CONFLICT DO NOTHING）+ 唯一约束做幂等写。
5. **金币**：`users.balance`（numeric(14,2)）；所有变动写 `user_balance_log`（direction 1收/2支, scene, before/after, ref_id）。发奖模式参考 checkin/redeemcode。
6. **常量**：每模块 `xxSiteId = 1` 单站点样板。
7. **迁移**：goose，`manifest/sql/migrations/`，**下一个编号 00032**。`bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`。先 migrate 再重启（GoFrame 启动缓存表结构）。
8. **类型坑**：`g.Model` 是函数不是类型，Model 变量类型是 `*gdb.Model`；事务回调 `func(ctx, tx gdb.TX)`。
9. **gofmt**：落盘前必须 `gofmt -e`（语法）+ `gofmt -l`（格式）全过。
10. **git**：助手绝不跑任何 git 命令（会留 index.lock），只写提交说明由用户在 Mac 提交。
11. **IDE**：改过的文件用户需重载编辑器标签页，防止旧缓存覆盖。
12. **敏感词**：`filter_word` 表（Phase 1 ops 模块），UGC 内容用 comment/post 模块里的 hitFilterWord 模式全量载入匹配。

## 三、Phase 3 资金链路（已定设计，未实施）

> recharge 充值：finance 模块已有 recharge-orders/回调/套餐，**基本无需新建**，仅评估补前台查单接口。

1. **wallet 钱包**（增强）：前台 GET /wallet/balance、GET /wallet/waters（查 user_balance_log）；后台 POST /wallet/adjust（人工调账 ±，必写流水）。不做通用 consume——**由内容模块各自做 buy 接口**（服务端定价，防客户端传金额）。
2. **withdrawal 提现**（00033）：表 withdrawal(user, amount, fee, account_info jsonb, status, audit_by/at, remark)。状态机 1申请→2审核通过→4完成 / 1→5拒绝(退款) / 1→6用户撤回(退款)。申请即冻结（balance 条件扣款+流水），所有状态迁移用 `WHERE status=旧值` 条件更新保证幂等。前台 apply/my/cancel；后台 list/audit/mark-paid。
3. **coupon 优惠券**（00034）：coupon_tpl（满减/折扣, total/issued, per_limit, 有效期）+ user_coupon（快照, 1未用2已用3过期）。后台 tpl CRUD + grant 发放；前台 my 列表。核销留给下单链路接入时做。
4. **content_purchase 内容购买表**（00032，供 Phase 4 用）：(site,user,media_type,content_id) 唯一防重复买，amount、created_at。

## 四、Phase 4 内容媒资 + 搜索（已定设计，未实施）

**先做搜索基建**：迁移里 `CREATE EXTENSION IF NOT EXISTS pg_trgm`（contrib 自带），标题列建 GIN trgm 索引加速 ILIKE；zhparser 需要用户先在 PG 安装扩展（`DO $$ ... EXCEPTION` 块守护，装不上不阻塞迁移）。

1. **comics 漫画**（大头）：comics(title/author/cover/intro/tags jsonb/category/is_free/price/counts/status审核) + comics_chapter(seq, pics **jsonb 图片数组**, is_free)。前台 list/detail/chapters/read（付费章节查 content_purchase，未购导 buy）+ POST /comics/buy（事务: 服务端价格扣款+purchase+流水）。后台作品 CRUD+审核 + 章节 CRUD。
2. **novel 小说**：同构，chapter.content 为 text，阅读接口分页。
3. **photo 图集**：单表 photo_album + pics jsonb。前台 list/detail；后台 CRUD。
4. **publish 投稿**：user_publish(type/title/intro/cover/resource jsonb/status审核/reject_reason)。前台 submit/my；后台 list/audit。
5. **search 搜索**：GET /search?keyword=&type= 跨 video/post/comics/novel/photo 标题 ILIKE（trgm 索引），命中即 hot_search.search_count+1（InsertIgnore + Counter）；GET /search/hot 复用 hot_search。
6. **media 视频**：与 PaaS my_media 媒资中心重叠，**复用勿照搬**——my_service.video 表已存在，只补前台浏览接口，文件/转码全走 my_media + my_play（统一播放接入文档已在总后台）。
